## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase email link → reset-password page | Recovery token arrives via URL hash; Supabase JS SDK validates it automatically |
| reset-password form → supabase.auth.updateUser | New password submitted client-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Spoofing | Recovery token validation | accept | Supabase SDK handles token extraction from URL hash and validates expiry; no custom token logic |
| T-03-02-02 | Information Disclosure | Password field visibility | mitigate | Both password inputs use `type="password"` — browser masks input |
| T-03-02-03 | Tampering | Weak password accepted | accept | Supabase enforces minimum password policy in project settings; front-end does not duplicate this check |
</threat_model>
