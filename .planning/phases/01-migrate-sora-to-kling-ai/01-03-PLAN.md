Error code patterns for errors.kling.* mapping:
- HTTP 429 or code indicating rate limit → return error key "rateLimit"
- HTTP 400 with content policy message → return error key "contentPolicy"
- HTTP 503 or model unavailable → return error key "modelUnavailable"
- All other errors → return error key "unknownError"

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → POST /api/generate | User-supplied: prompt, model, duration, size, image file |
| /api/generate → api.klingai.com | JWT in Authorization header; Kling receives finalPrompt, model_name, callback_url |
| api.klingai.com → callback_url | Kling will POST webhook events to this URL (handled in plan 04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | model parameter from client | mitigate | getCreditCost(model) returns 1 for unknown models (not an error, but acceptable); add explicit model validation: check that model is one of ["kling-v1", "kling-v1-5", "kling-v2"] and return 400 if not — prevents a client sending an arbitrary string as model_name to Kling |
| T-03-02 | Spoofing | JWT token in Authorization header | mitigate | generateKlingToken() generates a fresh HS256 JWT per request signed with KLING_SECRET_KEY; token expires in 30 min; secret never leaves server |
| T-03-03 | Information Disclosure | Kling API error details in response | mitigate | Error response returns `errors.kling.*` key string, NOT the raw Kling API error body; internal details (status codes, Kling error messages) are logged server-side only |
| T-03-04 | Tampering | callback_url field in Kling request | accept | callback_url is constructed server-side from NEXT_PUBLIC_APP_URL env var — not from client input; client cannot redirect Kling webhooks to an attacker-controlled URL |
| T-03-05 | Denial of Service | Kling rate limit (HTTP 429) | mitigate | 429 is caught and returned as errors.kling.rateLimit with 500 status to client; credits are refunded; no retry loop that could amplify the DoS |
</threat_model>
