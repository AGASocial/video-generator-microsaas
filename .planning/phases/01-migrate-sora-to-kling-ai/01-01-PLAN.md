  <four-questions>
    **Q1: Webhook signature header names (CRITICAL — blocks plan 04)**
    - What is the exact HTTP header name carrying the signature? (e.g., `X-Kling-Signature`, `Kling-Signature`, `Authorization`?)
    - What is the exact HTTP header name carrying the timestamp? (e.g., `X-Kling-Timestamp`, `Kling-Timestamp`?)
    - If there is no separate timestamp header, where does the timestamp come from?

    **Q2: Webhook signing payload format (CRITICAL — blocks plan 04)**
    - How is the signed payload constructed? Options:
      a. `${timestamp}.${rawBody}` (OpenAI / Stripe style)
      b. Just the raw body, no timestamp prefix
      c. Some other format — document exactly
    - What encoding is the signature in? hex or base64?
    - What HMAC algorithm? (HS256/SHA-256 is assumed)

    **Q3: Exact model name strings (HIGH — blocks plan 03)**
    - What are the accepted `model_name` values for the `/v1/videos/text2video` endpoint?
    - Are they: `kling-v1`, `kling-v1-5`, `kling-v2` (as assumed in CONTEXT.md D-01)?
    - Or a different format (dots, underscores, version numbers)?

    **Q4: Image-to-video request format (MEDIUM — blocks plan 03)**
    - What is the endpoint path for image-to-video? (`/v1/videos/image2video` is assumed)
    - What is the field name for the reference image? (`image`, `image_url`, `image_file`?)
    - Does it accept a URL or require base64? Or both?
    - Are there any additional required fields for i2v vs text2video?
  </four-questions>
